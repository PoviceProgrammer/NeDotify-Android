# Приёмка Android после разрешённой свежей сборки

Статус: **не выполнена**. Компиляция instrumentation не равна этим проверкам.
Старый APK 0.2.0 не годится для приёмки нынешних исходников.
Использовать отдельный профиль Android и собственные тестовые файлы/аккаунты.

Автоматические instrumentation-тесты настроены на `IsolatedAndroidTestRunner`:
стандартный Application, временные каталоги APK тестов, отдельные DB/DataStore,
SharedPreferences в памяти. Сначала выполнить `RunnerIsolationTest`. Он не
запускает production Application/MediaSessionService и не подтверждает их работу.
Ручные проверки настоящего приложения выполняются в отдельном тестовом Android-
профиле; рабочая библиотека пользователя не изменяется.

## Обязательные сценарии

**D01 / C.** Чистый запуск, существующий профиль Room v1/v2/v3→v4; библиотека и история
   сохраняются. Старые/повреждённые DataStore значения не блокируют запуск.
**D02 / C.** SAF/MediaStore: разрешить/отклонить, выбрать файлы, теги/обложки,
   перезапуск с URI grant, переместить файл, повторно связать. Общее разрешение
   не требуется для SAF. Сканирование не удаляет пользовательские записи.
**D03 / C.** Local/SoundCloud progressive/VOD HLS: play/pause/seek/next/previous/repeat/
   shuffle, ошибка и один retry, истёкший URL, пауза во время retry.
   Проверить настоящий звук, а не только движение прогресса.
**D04 / C.** Очередь: выбрать/переместить/удалить текущий/следующий/последний трек,
   очистить во время подготовки, перезапустить, восстановить на паузе;
   shuffle traversal сохраняется, новые Flow-треки добавляются после него.
**D05 / C.** Crossfade 0/1/6/12 секунд: настоящий переход двух декодеров, короткий трек,
   repeat-one/all, shuffle, seek/смена очереди/ошибка в начале/конце fade,
   stalled incoming. После ручной паузы звук сам не возобновляется.
**D06 / C.** AudioFocus: другое музыкальное приложение/звонок, duck/transient/permanent,
   noisy при отключении проводных/BT наушников; поздний gain после паузы.
   Одна сессия/медиауведомление, управление гарнитурой/экраном блокировки.
**D07 / C.** EQ/бас/пространственный эффект: поддержка и отсутствие поддержки, смена
   audio session, настройка при crossfade, отсутствие clipping/утечки эффектов.
   Два быстрых переключения и две разные EQ-полосы сохраняются одновременно.
**D08 / C.** FGS: Home/блокировка/длительный фон/убийство Activity/процесса,
   повторный controller bind; чужой недоверенный controller отклоняется.
**D09 / C.** Flow: пустая/малая/большая коллекция, offline, autoplay у конца shuffled
   очереди, нет повторов текущей очереди, ошибочный источник не вызывает цикл.
**D10 / C.** Smart playlists: все фильтры, 0/1/много треков, обновить избранное/скачивание/
    историю/правила, переименование, удаление; broken rules→исправление.
**D11 / C.** Downloads: queued/preparing/downloading/paused/failed/complete/removing,
    отказ notifications, network loss/resume/process death, параллельный лимит,
    мало места, pause/remove/restart race. HLS/seek в airplane mode, без сети.
    Удаление offline сохраняет избранное/плейлисты.
    Создать очередь до завершения загрузок, дождаться их завершения, включить
    offline на локальном/удалённом треке: следующие скачанные элементы играют.
**D12 / C.** JSON v1/v2 и desktop DB: preview/cancel/merge, повтор, конфликт/повреждение/
    oversized/нестандартная схема. Исходная DB побайтово не меняется, история
    не удваивается, Windows-путь не становится доступным Android-файлом.
**D13 / C.** Spotify: реальный собственный Client ID/redirect, cancel/state/срок/replay,
    холодный запуск callback/rotation, refresh/401/logout; tokens не в логах.
    Проверить ограничения доступа API аккаунта, metadata≠playable preview.
**D14 / C.** Яндекс: собственный OAuth, отказ/отзыв/401, каталог/плейлисты/полный трек,
    права аккаунта. В redirect/CDN не утекает токен.
**D15 / C.** Keystore: перезапуск/процесс, повреждённая запись/alias, повторный вход.
    Токены не попадают в JSON и системный backup.
    Выход/смена аккаунта во время HTTP 200/401 и пагинации не возвращает прежние
    данные; новый аккаунт не использует подписанные URL прежнего аккаунта.
**D16 / C.** Поиск: debounce/IME/история, источники и «Все», partial success,
    пустота/ошибка/повтор, реальные artist/album groups и запуск их очереди.
**D17 / U.** Lyrics: все источники, правильная версия/исполнитель/длительность, synced/
    plain/instrumental/not-found/error/retry; ручной scroll/return/seek,
    кэш offline после процесса, предыдущий трек не оставляет текст.
**D18 / C.** Reports: wall-clock без seek inflation и double counting crossfade,
    пауза/повтор/полночь/DST, 7/30/all и сравнение, отсутствующий трек истории.
    Повторная привязка файла и смена stream→offline того же трека сохраняет
    одну сессию; явный replay создаёт следующую.
**D19 / U.** UI по design/reference.png: 320/360/411dp, планшет/landscape/разделённый экран,
    клавиатура, insets, 200% шрифт/TalkBack/RTL, длинные имена/нет обложки,
    пустота/загрузка/ошибка; все меню и диалоги достижимы.
**D20 / U.** Light/dark/system, 4 акцента+Dynamic Color, фон/glass/power saver/API26–30
    fallback, animation scale=0. Проверить переключение на играющем треке.
    Отдельно проверить первый кадр светлой темы.

**D21 / V.** Общие токены и визуальная сверка: одна версия шрифта, данные,
размер окна и тема. Цвета токенов совпадают точно; ключевые размеры имеют допуск
2 dp. Native screenshots сравниваются на одном зафиксированном Android-стенде.
Каждое намеренное расхождение записывается с причиной и владельцем.

**D22 / L.** Длинная библиотека и быстрые команды при подготовке/загрузке:
UI остаётся отзывчивым, устаревшая команда не применяется к новому треку,
нет бесконечных повторов и сетевого/дискового I/O на UI-потоке.

## Свидетельства

Зафиксировать версию Android/модель/API, хэш нового APK и source manifest,
результат каждого пункта, logcat без секретов, screenshots home/search/library/
settings/profile/player в light/dark и узком/широком окне.
Независимые ревью должны ссылаться на текущий SOURCE_SHA256, а не старый baseline.

## Владение и машинная проверка

V организует выполнение всех D01–D22 и собирает доказательства; C/U/L в заголовках
отвечают за корректность своей области. Все сценарии сейчас **NOT_RUN**.
`implementation/scenarios.json` содержит их версионируемую спецификацию.

Для каждого запуска нужен `implementation/device-results.json`: sourceSha,
apkSha256, executedUtc, device.model, device.api, массив scenarios с уникальными
D01–D22, status (PASS/FAIL/BLOCKED/NOT_RUN), непустой actualResult, evidence и defects.
Верхний openDefects перечисляет незакрытые дефекты и severity. Реальные результаты
не включаются в source digest: иначе доказательство меняло бы проверяемое дерево.

`tools/check-device-acceptance.ps1 -SourceSha <sha> -ApkSha256 <hash> -EvidenceRoot <directory>` проверяет
уже существующий отчёт. NOT_RUN, отсутствие свидетельства, другой source/APK
и открытые S0/S1 блокируют приёмку. evidence содержит относительные пути к
существующим непустым локальным файлам внутри явно указанного каталога. Выход
за его пределы, символические ссылки и junctions отклоняются. Скрипт не собирает
APK и не запускает устройство.

Компиляция instrumentation, флаг isPlaying, веб-прототип и HTTP-проба не доказывают
слышимый звук на Android. Звуковой сценарий требует фактической проверки звука.
