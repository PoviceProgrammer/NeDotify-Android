## 5. Дефекты

### P0
P0-дефектов не обнаружено. Потенциально критичный риск (отсутствие `POST_NOTIFICATIONS`) отнесён к P1, так как может приводить к сбою воспроизведения на Android 13+.

### P1

**P1-1. Отсутствует разрешение `POST_NOTIFICATIONS`**
- Файл: `app/src/main/AndroidManifest.xml:3-9` (раздел `<uses-permission>`; нет строки `POST_NOTIFICATIONS`)
- Сценарий: запуск воспроизведения на Android 13+ (API 33+), когда разрешение не выдано.
- Последствие: Media3 не сможет показать уведомление foreground-сервиса; возможен `SecurityException`/остановка сервиса и отсутствие фонового воспроизведения.
- Исправление: добавить `<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />` и запросить разрешение во время выполнения в `MainActivity.kt` для API 33+.

**P1-2. `StreamCache.invalidate()` не отменяет выполняющееся разрешение URL**
- Файл: `app/src/main/java/ru/nedotify/app/data/StreamCache.kt:13`
- Сценарий: повтор после истечения URL, когда `resolve` уже выполняется; `repository.invalidate(id)` вызывается, но `inflight[id]` остаётся.
- Последствие: `get()` может вернуть устаревший/истёкший `ResolvedStream`, воспроизведение падает по 403/истечению.
- Исправление: в `invalidate` также удалять (и при необходимости отменять) `inflight[id]`.

**P1-3. Восстановление после ошибки плеера не возобновляет воспроизведение**
- Файл: `app/src/main/java/ru/nedotify/app/player/PlaybackService.kt:106-122`
- Сценарий: ошибка потока, успешный повторный `resolve` + `player.prepare()`.
- Последствие: если `playWhenReady` был true, после `prepare()` трек может остаться на паузе.
- Исправление: сохранять `playWhenReady` и вызывать `player.play()` после успешного `prepare()`, либо не сбрасывать готовность.

**P1-4. Нет runtime-обработки отсутствующего трека в очереди**
- Файл: `app/src/main/java/ru/nedotify/app/player/PlaybackService.kt:73-87`
- Сценарий: очередь содержит трек, удалённый из БД; `onAddMediaItems` вызывает `resolveItem`, который бросает `SourceFailure`.
- Последствие: `awaitAll()` падает, `future.setException`, воспроизведение всей очереди не начинается.
- Исправление: пропускать отсутствующие треки (или возвращать ошибку только для текущего), не ронять всю очередь.

### P2

**P2-1. История прослушивания не учитывает перемотку**
- Файл: `app/src/main/java/ru/nedotify/app/player/ListeningClock.kt:4-12` (и использование в `PlaybackService.kt:90-98`)
- Сценарий: пользователь перематывает трек вперёд/назад во время воспроизведения.
- Последствие: `listenedMs` может не совпадать с реально прослушанным временем (особенно при перемотке назад).
- Исправление: сбрасывать/корректировать часы при `seekTo` или вычислять прослушанное время по дельте позиции плеера.

**P2-2. `MusicViewModel.play` синхронно пишет в БД на main thread для всех треков очереди**
- Файл: `app/src/main/java/ru/nedotify/app/ui/MusicViewModel.kt:72-84`
- Сценарий: запуск длинного плейлиста.
- Последствие: возможны подтормаживания UI/ANR.
- Исправление: вынести `repository.remember(it)` в `Dispatchers.IO` (batch/параллельно) до `setMediaItems`.

**P2-3. `onAddMediaItems` выполняет чтение БД на main thread**
- Файл: `app/src/main/java/ru/nedotify/app/player/PlaybackService.kt:73-87`
- Сценарий: большая очередь.
- Последствие: задержка старта воспроизведения.
- Исправление: перенести разрешение `MediaItem` в IO-контекст или подготовить элементы заранее.

**P2-4. `restore` последовательно разрешает треки на main thread**
- Файл: `app/src/main/java/ru/nedotify/app/player/PlaybackService.kt:124-146`
- Сценарий: восстановление длинной очереди после перезапуска.
- Последствие: долгий запуск сервиса, возможный ANR.
- Исправление: параллельное/IO-разрешение с ограничением, с сохранением порядка.

**P2-5. `cancelAll()` отменяет in-flight, но не очищает `inflight` map**
- Файл: `app/src/main/java/ru/nedotify/app/data/StreamCache.kt:14`
- Сценарий: включение офлайн-режима при активных запросах.
- Последствие: `inflight` может содержать отменённые `Deferred`, повторный `get` может дожидаться отменённой задачи.
- Исправление: очищать `inflight` после отмены.

**P2-6. `favorite()` может перезаписать метаданные устаревшим `Track`**
- Файл: `app/src/main/java/ru/nedotify/app/ui/MusicViewModel.kt:92` и `app/src/main/java/ru/nedotify/app/data/Models.kt:43-46`
- Сценарий: избранное для трека, метаданные которого изменились после добавления в очередь.
- Последствие: `remember(track)` может перезаписать актуальные поля старыми значениями.
- Исправление: в `favorite()` обновлять только флаг `favorite`, не перезаписывать метаданные.

**P2-7. `importUris` не обновляет уже существующие треки**
- Файл: `app/src/main/java/ru/nedotify/app/data/LibraryRepository.kt:37-45`
- Сценарий: повторный импорт того же URI после изменения файла/имени.
- Последствие: старые метаданные остаются.
- Исправление: обновлять `title`/метаданные при повторном импорте, сохраняя `favorite`/`addedAt`.

### P3

**P3-1. Нет UI удаления/переименования плейлистов**
- Файл: `app/src/main/java/ru/nedotify/app/ui/MusicApp.kt:194-222` (нет действий delete/rename)
- Сценарий: управление плейлистами.
- Последствие: пользователь не может удалить/переименовать плейлист из интерфейса (только через БД).
- Исправление: добавить пункты меню/диалоги, используя `LibraryDao.deletePlaylist` и `putPlaylist`.

**P3-2. Устаревшие записи MediaStore не удаляются при сканировании**
- Файл: `app/src/main/java/ru/nedotify/app/data/LibraryRepository.kt:46-59`
- Сценарий: удаление файла из медиатеки устройства.
- Последствие: трек остаётся в библиотеке с нерабочим URI.
- Исправление: удалять треки, отсутствующие в результате сканирования (или помечать недоступными).

**P3-3. `retryCount` не сбрасывается при ручном повторном запуске того же трека**
- Файл: `app/src/main/java/ru/nedotify/app/player/PlaybackService.kt:106-109`
- Сценарий: повторный запуск трека после ошибки без смены трека.
- Последствие: второй автоматический retry не выполняется.
- Исправление: сбрасывать `retryTrack`/`retryCount` при явном `onPlayWhenReady`/`prepare`.

**P3-4. Отсутствие contentDescription у обложек и прогресс-индикаторов**
- Файл: `app/src/main/java/ru/nedotify/app/ui/Design.kt:73-78` (Cover), `app/src/main/java/ru/nedotify/app/ui/MusicApp.kt:108` (LinearProgressIndicator)
- Сценарий: TalkBack.
- Последствие: экранный диктор объявляет меньше контекста.
- Исправление: добавить contentDescription для обложек/прогресса.

**P3-5. Большие шрифты могут нарушать вёрстку (не проверено на устройстве)**
- Файлы: `app/src/main/java/ru/nedotify/app/ui/MusicApp.kt` (MiniPlayer, TrackRow, PlayerScreen)
- Сценарий: системный масштаб шрифта 200%.
- Последствие: возможное переполнение строк/кнопок.
- Исправление: проверить и добавить `maxLines`/`weight`/адаптивные высоты.

**P3-6. `windowBackground` всегда тёмный**
- Файл: `app/src/main/res/values/styles.xml:5`
- Сценарий: светлая тема при запуске.
- Последствие: возможная тёмная вспышка до отрисовки Compose.
- Исправление: сделать фон темы зависимым от светлой/тёмной темы или прозрачным с обработкой в Compose.

**P3-7. `playlistSelection` и `scrub` не сохраняются при гибели процесса**
- Файлы: `app/src/main/java/ru/nedotify/app/ui/MusicApp.kt:40-42`, `PlayerScreen` (`scrub` через `remember`)
- Сценарий: восстановление после убийства процесса.
- Последствие: сброс выбранного плейлиста/позиции перемотки.
- Исправление: использовать `rememberSaveable` для `scrub` и сохранять `playlistSelection`.

**P3-8. `Cover` не обрабатывает ошибки загрузки изображения**
- Файл: `app/src/main/java/ru/nedotify/app/ui/Design.kt:73-78`
- Сценарий: битый/недоступный URL обложки.
- Последствие: остаётся иконка-заглушка (приемлемо), но нет явного состояния ошибки.
- Исправление: добавить обработку ошибки Coil при необходимости.

## 7. Итог

Исходники проверяемой версии соответствуют `SOURCE_SHA256.txt` (39/39). Сборка и 8 unit-тестов проходят, lint без ошибок, APK собран. Код реализует заявленный первый проход, ограничения PORTING_STATUS в целом честны. Обнаружены дефекты (в основном P1–P3), наиболее важные: отсутствие `POST_NOTIFICATIONS`, некорректная инвалидация in-flight в `StreamCache`, отсутствие возобновления воспроизведения после ошибки, учёт перемотки в статистике, потенциальные ANR при больших очередях.
