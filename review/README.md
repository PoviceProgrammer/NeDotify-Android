# review/ — что где лежит

Каталог артефактов проверки Android-порта. Файлы делятся на четыре группы:
**текущие** (описывают дерево на сейчас), **история** (описывают прошлое
состояние и доказательством не являются), **брифы** (задания ревьюерам) и
**инструменты** (то, что эти файлы проверяет и перегенерирует).

## Текущие артефакты

| Файл | Что это |
|---|---|
| `SOURCE_SHA256.txt` | манифест снимка исходников: SHA-256 каждого файла дерева `android/`, пути относительные. Проверяется скриптом `VERIFY.ps1` |
| `TEST_SUMMARY.json` | числа последнего прогона (JVM-тесты, lint, инструментальные тесты, снимок) **и** то, откуда взято каждое число |
| `VALIDATION.md` | те же числа, написанные для человека. Файл **генерируется** `tools/update-review.ps1` вместе с `TEST_SUMMARY.json` — править руками нельзя, иначе артефакты разойдутся |
| `SNAPSHOT.json` | текущее состояние дерева: сколько файлов в манифесте, сколько тестов, что собрано линтом, что **не** собрано (APK, устройство) |
| `REMEDIATION_A*_FIX.md` | отчёт о правке по каждой области ремонта (A3…A8) |
| `REVIEW_BRIEFS.md` | общий бриф: контракт каждой области и правила, которые связывают всех |
| `ARBITRATION_*.md` | вход для арбитра: сводка находок двух независимых ревью по каждой группе областей |

## Брифы ревьюеров

| Файл | Что это |
|---|---|
| `BRIEF_A.md` | задание независимому ревьюеру A (MEDIA-сессия, данные, Room, OAuth, провайдеры) |
| `BRIEF_B.md` | задание независимому ревьюеру B (сценарии, Compose, навигация, доступность, производительность) |

Имена `BRIEF_A.md` / `BRIEF_B.md` — по REG P2-41: файлы содержат **задание**,
а не отчёт, и старые имена `REVIEW_A.md` / `REVIEW_B.md` читались как отчёты.
Сами отчёты лежат в `received/`.

## История (доказательством не является)

`PRE_AUDIT2_*`, `PRE_BUGFIX_*`, `STAGE4_*`, `BACKUP_*`, `BASELINE_*`,
`DOWNLOADS_*` — снимки и сводки прошлых состояний дерева. Они показывают,
как менялись числа, и нужны для сравнения, но **не** описывают текущий код.
`BUGFIX_2026-10-19.md`, `REVIEW_RESOLUTION.md` и журналы (`*.log`, `*.json`
проверок) — та же категория.

## Инструменты

| Файл | Что это |
|---|---|
| `VERIFY.ps1` | проверка снимка: печатает новые, изменённые, удалённые и «больше не источники» файлы и завершается с ошибкой, пока манифест не перегенерирован |
| `../tools/update-review.ps1` | перегенерация `TEST_SUMMARY.json`, `VALIDATION.md` и `SNAPSHOT.json`; с ключом `-RefreshSnapshot` — ещё и манифеста |
| `../tools/SourceSnapshot.ps1` | правила снимка и сравнение дерева с манифестом |

## Чего в этом каталоге нет и не должно быть

* **APK.** Сборка APK запрещена (`android/AGENTS.md`); ни один артефакт
  здесь не описывает установленное приложение.
* **Результата на устройстве.** 66 инструментальных `@Test` **скомпилированы,
  но ни разу не выполнены**: нет ни устройства, ни эмулятора. Всё, что здесь
  написано про устройство, — это план приёмки (`DEVICE_ACCEPTANCE.md`) и
  честная отметка «не выполнено».
* **Данных пользователя.** Ни один файл не содержит ни токена, ни базы
  `~/.nedotify/`, ни файлов библиотеки устройства.
