# Решения по двум внешним ревью — 2026-10-18

Рабочий проект: `NeDotify/AURA_Music_backup/AURA_Music_main/android`, package
`ru.nedotify.app`. Другая папка `NeDotify/android` не менялась.

**A** — [первый полученный отчёт](received/REVIEW_A_2026-10-18.txt),
**B** — [второй](received/REVIEW_B_2026-10-18.txt). Оба проверили 39 файлов
старого снимка с SHA256 манифеста
`b8c5f20ee50f9c252257c0c4c5a00fef50f624714bdcbdb1770c03b00ceb4b12`.
Он сохранён как `BASELINE_SOURCE_SHA256.txt`. Текущий снимок — `SOURCE_SHA256.txt`.
Ни один из полученных отчётов не является ревью последующих исправлений.
Субагенты автором исправлений не запускались.

После этого разбора добавлен этап 0.2.0: постоянные офлайн-загрузки. Он имеет
свой новый сценарий download/dataSync-уведомлений и запрос POST_NOTIFICATIONS;
это не меняет приведённое ниже исключение для media-session уведомления.
Сборочные файлы теперь `*.gradle` (Groovy DSL), Kotlin приложения сохранён.
Свежие подписи downloader получает отдельно от StreamCache плеера, чтобы
скачивание текущего трека не отменяло его активное разрешение URL.

«Исправлено» ниже означает изменение кода с указанной доступной проверкой,
а не подтверждение работы на телефоне. Результаты сборки — `VALIDATION.md`.

| B P3-22: протокол меняется | Страховка: SoundCloud выбирает протокол, соответствующий MediaSource; resolver сравнивает actual MIME с ожидаемым HLS и даёт понятную ошибку при смене. | B P3-23: data extraction | Добавлены явные cloud/D2D exclusions и правила старого backup. Не переносим непригодные на другом телефоне content URI автоматически; переносимая резервная копия ещё не реализована. Проверено lint/build, D2D на устройствах — нет. |

Дополнительно исправлен порядок cache/resolver: `ResolvingDataSource(CacheDataSource(upstream))`.
CacheDataSource выбирает ключ уже по реальному URL, чтобы старая redirect/manifest
метаинформация под постоянным ID не закрепляла истёкшую подпись. Автоматическое
обновление URL с заполненным кэшем требует проверки на устройстве.

## Уточнённые и неподтверждённые выводы

| Отчёт, пункт | Решение |
|---|---|
| A P1-1; B P2-3: POST_NOTIFICATIONS | Не подтверждается. Уведомления media session освобождены от этого permission; foreground service не требует его выдачи для старта. Лишний permission prompt для единственного media-уведомления не добавлен. Другим будущим уведомлениям разрешение может потребоваться. [Официальные исключения Android](https://developer.android.com/develop/ui/compose/notifications/notification-permission#exemptions). |
| A P1-3: prepare снимает playWhenReady | Утверждение не подтверждено: prepare сохраняет это поле. Сохранён текущий пользовательский intent, pause отменяет pending recovery; нет безусловного play после паузы. Возобновление и гонки требуют устройства. [API ExoPlayer](https://developer.android.com/reference/androidx/media3/exoplayer/ExoPlayer). |
| A P2-1: время после seek | Замена на дельту позиции была бы ошибкой: пропущенные минуты не прослушаны, повторно услышанные секунды учитываются. Монотонный clock работает только при isPlaying, пауза/буфер исключены. `ListeningClockTest`, `ListeningHistoryTest`. |
| A P2-2/3/4: suspend Room делает SQL на main | Room сам диспетчеризует suspend queries. Реальная лишняя N-подготовка устранена батчами; это не доказанный main-thread ANR. [Асинхронные запросы Room](https://developer.android.com/training/data-storage/room/async-queries). |
| B P2-10: signature permission не ломает Auto | Гарантия неверна: сторонние/system контроллеры не обязаны иметь подпись приложения. Экспорт оставлен для системной интеграции, собственные/trusted контроллеры проверяются, произвольные URI не принимаются. Остаточная поверхность внешнего bind/start не объявляется устранённой; lint ExportedService не подавлен. [Официальная схема MediaSessionService](https://developer.android.com/media/media3/session/background-playback). |
| B P2-12: весь cache scan синхронно main | В Media3 1.11.1 конструктор запускает `ExoPlayer:SimpleCacheInit`, открывая condition до initialize. Поэтому описание полного main-thread scan неверно. Время создания потока/доступа к файловой системе всё равно требует профиля устройства. [Исходник SimpleCache](https://github.com/androidx/media/blob/1.11.1/libraries/datasource/src/main/java/androidx/media3/datasource/cache/SimpleCache.java). |
| B P3-17: getMediaItemAt даёт shuffled order | Индексы остаются исходными. Сохранять точный traversal нужно потому, что shuffle может генерироваться заново, а не из-за двойного перемешивания возвращаемого списка. [Media3 playlists](https://developer.android.com/media/media3/exoplayer/playlists#shuffle_mode). |
