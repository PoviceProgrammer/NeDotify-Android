# NeDotify Android

Нативный Kotlin / Compose / Room / Media3-порт, без Python и WebView.
Мобильный референс: [design/reference.png](design/reference.png).
Состояние всех этапов и ограничения: [PORTING_STATUS.md](PORTING_STATUS.md).
Проверки исходников: [review/VALIDATION.md](review/VALIDATION.md).

**Новый APK сейчас не собирается по указанию пользователя.** Сохранённый APK
0.2.0 не содержит JSON/desktop-перенос, новый UI и функции последнего этапа.
`Run-Android.bat` **не устанавливает** этот старый APK: `run-emulator.ps1`
требует явный `-ApkPath` и без него завершается с ошибкой. Для тестирования
нового кода позже потребуется разрешение собрать свежий APK.

## Проверка исходников без APK

Зафиксированы AGP 9.1.1, Gradle 9.3.1, встроенный Kotlin 2.2.10, Compose BOM
2026.09.00, Media3 1.11.1, Room 2.8.5, WorkManager 2.12.0, min API 26,
compile/target API 37. JDK 17 или 21, SDK Platform 37.0 / Build Tools 36.0.0.
Groovy DSL обходит воспроизведённую на этом ПК ошибку Gradle Kotlin DSL.

В корне desktop checkout:

    ./android/verify.ps1 -Tasks ':app:testDebugUnitTest,:app:lintDebug,:app:compileDebugAndroidTestKotlin'

При необходимости параметры -SdkPath и -JavaHome задают существующие SDK/JDK.
Скрипт создаёт ASCII junctions, восстанавливает исходные байты local.properties
и окружение в finally. Kotlin incremental отключён из-за метаданных junctions.
Команда не формирует APK. Компиляция Android-тестов не означает их выполнение.

**Где живёт SDK.** Android SDK должен стоять в **постоянном** месте
(`%LOCALAPPDATA%\Android\Sdk`), а не во временном каталоге: очистка
временного каталога уносит систему сборки вместе с ним. Канал указания SDK —
переменные окружения `ANDROID_HOME` / `ANDROID_SDK_ROOT`;
`android/local.properties` (файл машинно-локальный, в репозитории его нет) —
запасной путь. AGP отдаёт предпочтение файлу, поэтому `verify.ps1` на время
прогона записывает в файл ASCII-псевдоним SDK и восстанавливает исходные
байты в `finally`; `tools/run-unit-tests.ps1` файл вообще не трогает и
берёт SDK сначала из окружения. Псевдоним `<temp>/sdk` даёт ASCII-путь
даже тогда, когда сам SDK лежит в каталоге с не-ASCII именем.

Тот же набор задач без правки окружения (ASCII junctions создаёт сам,
local.properties не трогает):

    powershell -NoProfile -File android/tools/run-unit-tests.ps1 -Tasks ':app:testDebugUnitTest,:app:lintDebug,:app:compileDebugAndroidTestKotlin' -Summarize

В обычном окружении из android/:

    ./gradlew :app:testDebugUnitTest :app:lintDebug :app:compileDebugAndroidTestKotlin

Список допустимых задач — `android/tools/SourceTasks.ps1`: сборка APK и
задачи устройства запрещены (`android/AGENTS.md`), попытка вызвать их
останавливается до запуска Gradle.

## Зависимости, каталог версий и контроль целостности

| Файл | Что делает |
|---|---|
| `gradle/libs.versions.toml` | общий каталог версий: одна запись на библиотеку, версии плагинов и BOM |
| `app/gradle.lockfile` | состояние блокировки **модулей приложения**: зафиксированная версия каждого модуля каждой конфигурации `app/` (30 библиотек с своей версией + 6, версию которых задаёт BOM) |
| `buildscript-gradle.lockfile` | состояние блокировки **класспути плагинов** (AGP, Compose-плагин, KSP). Плагины применяются в корневом проекте, поэтому блокируются здесь: 123 строки, включая маркеры `com.android.application:…gradle.plugin:9.1.1` и остальных плагинов |
| `settings-gradle.lockfile` | состояние блокировки **каталога версий** в скрипте настроек: одна строка (`empty=incomingCatalogForLibs0`). Ни плагины, ни модули приложения здесь не заблокированы — их блокируют два файла выше |
| `gradle/verification-metadata.xml` | SHA-256 каждого артефакта, который может прийти из репозитория |
| `lint.xml` | настройки lint для всего дерева (см. ниже) |

* **Каталог и блокировка обязаны совпадать.** Блокировка сильнее объявленной
  версии: каталог с `core = "1.17.0"` при блокировке `1.18.0` молча собирает
  1.18.0. Проверка: `powershell -File android/tools/check-catalog-lock.ps1`
  — она **входит в `verify.ps1`** и в CI. Проверка сравнивает версию
  каждой библиотеки с записью блокировки, отдельно проверяет шесть
  библиотек, версию которых задаёт BOM (имя модуля должно быть в блокировке),
  и отдельно сообщает, если один и тот же модуль заблокирован несколькими
  версиями (у `org.xerial:sqlite-jdbc` это так: 3.46.1.3 в тестах и 3.41.2.2
  в класс-пате KSP).
* **Проверка зависимостей включена** и не отключается: артефакт, которого нет
  в `verification-metadata.xml`, останавливает сборку. Инструмент lint
  (`com.android.tools.lint:*:32.1.1`, uast, intellij-core, kotlin-compiler,
  groovy) тоже входит в метаданные — иначе `:app:lintDebug` падал до анализа.
* **aapt2 зависит от ОС.** В метаданных есть и Windows-, и Linux-сборка
  (`aapt2-9.1.1-14792394-windows.jar` и `-linux.jar`), иначе сборка на CI не
  проходит проверку.
* **Обновить метаданные** (только когда состав зависимостей изменился
  осознанно):

      powershell -File android/tools/run-unit-tests.ps1 -Tasks ':app:lintDebug' -RefreshVerificationMetadata
      powershell -File android/tools/run-unit-tests.ps1 -Tasks ':app:resolveAndLockDependencies' -RefreshLocks

  Метаданные проверяются **при скачивании**: артефакт, уже лежащий в
  локальном кэше Gradle, повторно не хэшируется. Поэтому «обновить
  метаданные» на тёплом кэше **не увидит** артефакты, которых в файле нет:
  сначала удалите их из `~/.gradle/caches/modules-2/files-2.1/` (или
  снимите кэш целиком) и только потом запускайте команду выше. Именно так
  были найдены `guava-parent-33.3.1-jre.pom`, `junit-bom-5.10.2.module` и
  `junit-bom-5.11.0-M2.module` — файлы, без которых свежий раннер падал на
  самом старте.


## Lint

Настройка гейта — `android/build.gradle`:

    lint { abortOnError = true; checkDependencies = false }

* **Ошибка останавливает сборку.** Предупреждение — нет.
* **Проверки зависимостей выключены** (`checkDependencies = false`): они
  требуют разобранного графа зависимостей и делают гейт функцией окружения.
* **Три детектора «доступна новая версия» выключены в гейте**
  (`android/lint.xml`: `NewerVersionAvailable`, `GradleDependency`,
  `AndroidGradlePluginVersion`). Они читают репозиторий **по сети** и
  кэшируют ответ в `app/build/intermediates/lint-cache/…/maven-versions/`;
  аудит измерил для **одного и того же** исходника 15, 13 и 4
  предупреждения — в зависимости от состояния кэша и сети. Гейт, чей
  результат зависит от сети, гейтом не является.
  Проверено на AGP 9.1.1: `checkDependencies = false` **не** убирает эти
  три детектора (модель lint пересобирается, а детекторы всё равно
  срабатывают) — поэтому они выключены здесь, явно и поимённо.
* **Информация не потеряна:** отдельная задача
  `:reportNewerVersions` печатает доступные новые версии каталога и
  **никогда** не роняет сборку. Она не входит в гейт.

    powershell -File android/tools/run-unit-tests.ps1 -Tasks ':reportNewerVersions'

* **PropertyEscape** — единственная проверка, выключенная **для одного
  файла**: `android/lint.xml` содержит
  `<ignore path="local.properties"/>`, то есть путь совпадает с **именем**
  файла, а не с каталогом одной машины. Файл машинно-локальный и
  gitignored, способ записи пути к SDK разный на каждой машине; проверка
  права насчёт формы, но не может ронять сборку из-за файла, которого нет в
  репозитории. `android/gradle.properties` при этом проверяется как обычно.


## Release-сборка (без сборки APK)

Конфигурация `android/app/build.gradle`; release-вариант проверен по
эффективной модели AGP, APK не собирался:

| Свойство | Значение |
|---|---|
| `release.applicationId` | `ru.nedotify.app` |
| `debug.applicationIdSuffix` | `.debug` → `ru.nedotify.app.debug` |
| `release.minifyEnabled` | `true` (задача `minifyReleaseWithR8` создана) |
| `release.shrinkResources` | `true` (задача `optimizeReleaseResources` создана) |
| `release.proguardFiles` | `proguard-android-optimize.txt` + `app/proguard-rules.pro` |
| `release.signingConfig` | `release`, значения из переменных окружения |

Подпись release задаётся переменными окружения:

    NEDOTIFY_KEYSTORE        путь к файлу подписи (.jks/.keystore)
    NEDOTIFY_STORE_PASSWORD  пароль хранилища
    NEDOTIFY_KEY_ALIAS       псевдоним ключа
    NEDOTIFY_KEY_PASSWORD    пароль ключа

Без `NEDOTIFY_KEYSTORE` release-вариант остаётся **неподписанным по
намерению**: AGP требует `storeFile/storePassword/keyPassword/keyAlias` при
упаковке и падает, а не выпускает немой APK. Debug-подпись — стандартная
`~/.android/debug.keystore`.

Проверить конфигурацию без сборки:

    powershell -File android/tools/run-unit-tests.ps1 -Tasks ':app:signingReport'
    powershell -File android/tools/run-unit-tests.ps1 -Tasks ':dumpVariantModel' -InitScript 'dump-variant-model.gradle'

## Снимок исходников и отчёт о проверках

* `review/SOURCE_SHA256.txt` — SHA-256 каждого исходника дерева; пути
  относительные, машинно-локальный путь в манифесте быть не может
  (проверяется при чтении манифеста).
* **Что входит в манифест.** `.kt .java .xml .gradle .properties .toml .ps1
  .bat .pro .jar .py .md .json .png .yml .yaml .txt .lockfile`, файл
  `gradlew`, `gradle.lockfile`, `app/gradle.lockfile`, схемы Room
  `app/schemas/*.json` и `.gitignore`. Файлы `review/*` (кроме `.ps1`) в
  манифест **не** входят: `TEST_SUMMARY.json` несёт хеш манифеста, и
  включение самого манифеста обесценивало бы его при каждой перегенерации.
* Отчёт о расхождении называет четыре списка: **новые**, **изменённые**,
  **удалённые** и **«больше не источники, но на диске»** — последний список
  появляется, когда манифест написан по более широкому правилу, чем текущее.
* Проверка: `powershell -File android/review/VERIFY.ps1` — печатает новые,
  изменённые и удалённые файлы и завершается с ошибкой, пока манифест не
  перегенерирован.
* Перегенерация (только когда все области закончили правку):

      powershell -File android/tools/update-review.ps1 -RefreshSnapshot

  Скрипт читает JUnit XML, текстовый отчёт lint и `@Test` в androidTest,
  записывает `review/TEST_SUMMARY.json` и **не** запускает Gradle.

## CI

`.github/workflows/android-source.yml` — на каждый push/PR, меняющий
`android/**`: снимок исходников, согласие каталога и блокировки, затем
`:app:testDebugUnitTest`, `:app:lintDebug`, `:app:compileDebugAndroidTestKotlin`.
APK не собирается. SDK ставится из репозитория (`platforms;android-37.0`,
`build-tools;36.0.0`), локальный путь к SDK не используется.

* **Шаг со снимком — «растяжка» для каждого обычного изменения.** Любой
  изменённый, добавленный или удалённый исходник валит шаг, пока манифест
  не перегенерирован (`tools/update-review.ps1 -RefreshSnapshot`). Это
  осознанно: снимок — то, что делает проверку повторяемой. В комментарии
  самого workflow это написано, чтобы правило не было сюрпризом.
* **Шаг с холодным кэшем.** Gradle проверяет контрольные суммы артефактов
  **при скачивании**: артефакт, уже лежащий в локальном кэше, повторно не
  пересчитывается. Поэтому CI прогоняет сборку ещё раз на **пустом**
  `GRADLE_USER_HOME` — там проверка метаданных действительно срабатывает.
  Без этого шага сбой метаданных проявился бы только у того, кто чистил
  кэш (и у каждого свежего раннера).


## Основные сценарии

- **Библиотека → Добавить файлы**: SAF с постоянным разрешением; либо
  **Настройки → Найти музыку на устройстве**: MediaStore с runtime permission.
  Читаются локальные теги и обложки. Через меню локального трека → «Указать файл»
  можно повторно связать файл, в том числе после переноса с ПК.
- **Поиск**: «Все», SoundCloud, экспериментальный YouTube Music, устройство;
  история, треки и группы исполнителей/альбомов из результатов.
- **Мини-плеер** открывает полный плеер: transport, seek, очередь, тексты,
  избранное. Очередь поддерживает перемещение/удаление, repeat/shuffle и
  восстанавливается на паузе с сохранённой позицией.
- **Главная → Flow**: микс из коллекции и измеренной истории. Autoplay добавляет
  следующую небольшую порцию; рекомендации не являются вымышленным чартом.
- **Библиотека → Умные**: создание/редактирование правил, реактивный список.
- **Профиль**: локальное имя/описание/фото и отчёты за 7/30 дней/всё время.
  Используется фактическое время; перемотка и crossfade не удваивают минуты.

Сервис владеет двумя ExoPlayer и одной стабильной MediaSession. UI подключается
MediaController и не владеет декодерами. Настройка темы не перезапускает сервис.
Одновременные декодеры используются только для реального crossfade, который
можно выключить. Единый AudioFocus/noisy владелец управляет обоими.

## Настройки

Оформление: светлая/тёмная/системная тема, четыре акцента и системный акцент
Android 12+, стекло с fallback, атмосферный фон, следование тексту.

Плеер: crossfade 0–12 секунд, autoplay, 5 полос EQ, бас и пространственный эффект.
Устройства без соответствующего AudioEffect показывают отсутствие поддержки.
Качество выбирает реально доступный полный поток; подпись «320 kbps» не
выдумывается. Квота LRU 64–1024 МБ применяется после перезапуска.

Текст: LRCLIB exact/search → NetEase → QQ → Genius, проверка идентичности,
plain/synced/instrumental/ошибка/повтор. Приватный кэш переживает процесс:
до 100 записей, 24 часа найденным / 10 минут отсутствующим; память до 20.
Синхронный текст поддерживает ручную прокрутку с возвратом и выбор строки.

## Подключения и каталоги

**Настройки → Музыка и хранилище → Spotify**: укажите собственный Client ID,
зарегистрируйте nedotify://oauth/spotify, начните PKCE-вход во внешнем браузере.
Client secret в приложение не добавляется. Доступность API зависит от настоящего
приложения/аккаунта; здесь живой вход не проверен. Spotify используется как
каталог метаданных: для аудио подбирается совместимая запись других источников.

**Яндекс Музыка**: собственный OAuth-токен проверяется сервисом; доступны каталог,
избранное и плейлисты. Полный MP3 разрешается только при наличии прав аккаунта;
preview не выдаётся за целый трек. Неофициальный API может измениться.

В каталоге можно слушать запись или импортировать открытый список: до 500 треков
за операцию, с числом подобранных/недоступных. Ошибка не добавляет фиктивное аудио.
Отмена окна отменяет подбор. OAuth сохраняется через Android Keystore AES-GCM,
не включается в библиотечные копии и не отправляется на CDN.

## Загрузки

Меню трека → **Скачать для офлайн**, затем **Библиотека → Скачанные**.
WorkManager хранит задания, максимум два одновременно; есть пауза/продолжение/
повтор/удаление. Offline приостанавливает сетевые задания. Отказ в разрешении
уведомлений Android 13+ не запрещает скачивание: состояние остаётся в UI.

Progressive/VOD HLS сохраняются штатными Media3-загрузчиками в files/offline-media,
отдельно от вытесняемого cache/audio. Это приватный полный offline-пакет,
не экспортированный MP3. Завершённый источник не имеет сетевого upstream.
Частичные загрузки, DRM без лицензии и эфиры не считаются доступными offline.

## Перенос библиотеки

**Настройки → Резервная копия библиотеки**: сохранить JSON или проверить копию
и подтвердить «Объединить». Формат v2 читает v1, переносит треки/избранное/
плейлисты/умные правила/измеренную историю. Повтор не удваивает историю.
Лимиты: 16 МиБ, 20 тыс. треков, 2 тыс. плейлистов, 100 тыс. связей/сессий.
Объединение атомарное; конфликты идентичности отклоняют импорт целиком.

**Импорт библиотеки ПК**: сначала закройте desktop-плеер, сделайте копию его
SQLite DB и выберите копию через системное окно Android. Задайте постоянное имя
источника: при повторном переносе с того же ПК используйте то же имя.
Источник читается READONLY, проверяется и преобразуется в тот же preview/merge.
Лимит DB — 128 МиБ. Windows-пути и аудиофайлы не переносятся; старая история
без отметки измеренного времени пропускается с пояснением.

Копии не включают аудио, очередь, персонализацию, OAuth или URI-разрешения.
Для локальных записей на другом устройстве надо выбрать файлы заново.

## Проверка на Windows

Подготовлен эмулятор API 36. Ранее по разрешению пользователя включён Windows
Hypervisor Platform; установка вернула RestartNeeded=true. Автоматического
рестарта не было, успешный запуск ускоренного Android не подтверждён.

Run-Android.bat / run-emulator.ps1 проверяет ускорение, открывает видимый
эмулятор и устанавливает сохранённый APK. **Для новых исходников это пока
устаревший APK.** Не запускайте launcher для приёмки нового кода до новой сборки.
Диагностика без установки: ./run-emulator.ps1 -CheckOnly.

После разрешённой свежей сборки выполните
[review/DEVICE_ACCEPTANCE.md](review/DEVICE_ACCEPTANCE.md).
Новых Android-скриншотов и подтверждения звука пока нет.

Живая JVM-проба запускается только по явной необходимости с
NEDOTIFY_LIVE_PROBES=1. Исторический результат 2026-10-18: SoundCloud — поиск,
HLS и первый фрагмент доступны; YouTube Music — поиск доступен, player требует
вход. Это HTTP-проверка, не проверка декодирования и фонового звука Android.
